# 微博纯 IP 属地分流

只代理微博 App 中真正承载 IP 属地判定信号的接口,其余 Feed 流、图片等媒体 CDN 直连。

## 依据

- `api.weibo.cn/2/carrier/get/info` 会回显服务器看到的客户端 IP(响应体为 `{"ip":"..."}`),是唯一经抓包证实的属地判定信号源。三次独立抓包验证有效,第三次为"发帖"场景专项抓包。
- 该接口只在 App 冷/热启动阶段调用一次,不是每次发帖都触发(此前版本描述有误,已修正)。
- `dns.weibo.cn` 是微博自建 HTTPDNS,用于解析 `sinaimg.cn` 图片 CDN,走的是明文 HTTP,必须和它解析的 CDN 走同一网络路径,否则会出现"代理视角最优 IP"和"实际连接路径"不一致的问题,因此直连。

## 为什么默认不做"路径级精确代理"

Surge / Loon 的 `[Rule]` 引擎按域名(证书 SNI)匹配,同一域名下不同路径若不开 MITM 无法区分。`api.weibo.cn` 大概率和登录/发帖一样做了证书锁定,贸然开 MITM 有导致发帖/登录失败的风险。默认规则因此以域名为最小颗粒度:CDN/HTTPDNS 摘出来直连,`api.weibo.cn` 整体代理——这是不牺牲账号安全前提下最接近"只代理属地信号"的方案。

## 精确模式(可选,默认关闭)

如果你已确认自己的证书环境不会被 `api.weibo.cn` 拒绝,想要"只代理 carrier/get/info、其余路径直连":

1. 取消 `.plugin` 文件里 `[MITM]` 下 `hostname = api.weibo.cn` 的注释
2. 取消 `[Rule]` 里那条 `URL-REGEX ...(?!2/carrier/get/info)... DIRECT` 的注释(必须在 `DOMAIN, api.weibo.cn, PROXY` 之前生效,否则精确模式不会真正生效)
3. 可选:取消 `[Script]` 段注释,加载 `scripts/weibo_ip.js` 作为保险层,清理响应体里可能残留的 `region_name` / `ip_location` 文字字段
4. 开启后先登录、刷新一次 Feed、发一条测试帖,确认没有报错再长期使用;出现异常立刻关闭 MITM

## 使用建议

- 装好后在插件配置页手动指定**固定单一节点**(select 类型策略组,不要用 url-test 自动测速),选延迟较低的地区
- 把本插件放在 `GEOIP,cn,DIRECT` 等国内直连规则之前,并排在其他同类规则集(如 anti-ip-attribution)之前加载
- 若同时使用微博去广告类插件,注意它可能对 `api.weibo.cn` 做独立的 MITM,出现异常建议分开排查
- 原插件的抖音部分自 1.9.6 起拆分为独立插件(抖音纯IP属地分流.plugin)

## 已知问题(排查参考,规则层面无法解决)

- 部分接口自带 3 秒客户端超时,冷启动首批请求建连慢时会被 App 自己取消
- 单次请求耗时 10+ 秒且更换手动固定节点后依旧,通常是节点当下连接质量问题,建议换节点
